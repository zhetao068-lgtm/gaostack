# 一次点击，如何避免发两次

发布图文和保存草稿的失败表现不同。浏览器转圈之后，编辑者可以刷新看草稿是否还在。但如果服务端已经把发表请求送到微信，网络超时就无法告诉我们文章究竟有没有发出去。这时用同一个按钮重试，可能造成重复发表。

稿栈在数据库里为每篇文章保留一条发布记录。提交前，它通过条件插入检查稿件仍是当前版本，并且数据库里尚无该稿的发布记录。同一份稿件从两个标签页同时提交，只有一个请求取得写入资格。取得资格的请求才继续上传封面并创建微信草稿。写入发生在服务端，所以刷新页面也不能重新拿到资格。

微信返回发布编号后，界面显示「微信处理中」。只有查询结果明确成功并带有公众号文章链接时，界面才显示已发表。如果网络在提交阶段断开，记录保留为「结果待核对」，编辑者可以用微信后台确认。数据库不能和微信建立一笔跨系统事务，因此这个做法优先避免重复提交，代价是部分故障需要人工核对。

仓库的本地测试用模拟微信接口验证并行请求只有一个成功提交、回执成功才进入已发表。测试不使用真实公众号，也无法用于推断生产服务的成功率。
