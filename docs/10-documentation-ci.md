# 文档更新也经过同一条检查流水线

稿栈仓库的检查工作流在推送和拉取请求时运行。文件没有路径筛选条件，因此只更新文档也会运行测试。检查作业依次执行测试、构建和构建产物语法检查，用于发现当前提交是否仍能完成这三个步骤。

工作流对仓库内容只申请读取权限。检出源码和安装 Node.js 的两个 Action 都指向固定提交，运行版本可以从配置中直接查看。当前配置使用 Node.js 24。

## 复现

打开仓库的 Actions 页面，选择 Checks，查看一次推送对应的运行。测试步骤运行 npm test，对应 package.json 中的 Node 测试命令。随后构建脚本把网页与服务端入口组合到 dist/server/index.js，最后的语法检查检查该文件能否被解析。

本次文章提交前在本地执行了同一组测试，结果为四项通过。远端运行的状态需在 GitHub 中另行核对。这里的流水线没有执行真实公众号发表，能够验证的是本地模拟覆盖的行为与构建过程。
