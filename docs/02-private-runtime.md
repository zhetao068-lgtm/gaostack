# 公开代码，为什么还需要锁住工作台

公开代码让同行可以看清如何提交稿件，却不必一并公开数据库、浏览器资料和云端设置。稿栈公开版从空目录建立，只复制程序所需的源码和数据库结构。这样既能复用其编辑和发布逻辑，又不会把旧提交或实际稿件带进公开历史。

工作台运行时还需要自己的访问边界。页面和 API 在处理请求前，通过 HTTPS 和独立访问密码确认请求者。之前用于专有托管环境的身份请求头不会在公开版中直接使用，因为换一个部署环境后，请求头不一定依然由受信任的代理写入。服务端接着核对写请求的来源，防止浏览器在另一网页里被诱导执行操作。

正式发表需要管理员在服务端单独启用。微信密钥通过部署端密钥管理传入。返回浏览器的只是状态与回执，错误日志也避免打印请求、稿件或上游响应。公开源码仍允许读者看到这些约束并复现它们。

剩余的风险主要留在运行环节。部署者需要给入口配置限速和日志权限，为数据库备份设定保留期，并对导出到电脑上的稿件负责。共享密码适合单人编辑，团队应使用有独立身份与审计记录的访问网关。
