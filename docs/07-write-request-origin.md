# 写接口为何检查请求来源

稿栈的写请求在认证之后，还会核对浏览器发来的 Origin。只有它与工作台请求地址的 origin 完全一致时，请求才会进入稿件处理逻辑。这意味着协议、主机和端口都参与比较。没有 Origin 的写请求也会被拒绝。

访问密码与来源检查处理的是不同问题。前者确认调用方持有凭证，后者限制浏览器中的跨站写入。即使用户已登录，另一个网站也不应借浏览器向工作台提交稿件。服务端验证同源条件，才能把界面中发起的操作与其他来源的调用区分开。

## 复现

运行 `node --test tests/publication.test.mjs`，查看 `rejects cross-origin writes and oversized JSON`。该测试向稿件写接口发送有效测试认证头，同时指定另一个示例域名作为 Origin。响应应为 403。测试用存储对象没有写入能力，因此若请求继续进入存储逻辑，也会暴露出来。

脚本客户端可以自行设置请求头，因此 Origin 检查始终需要和认证一起使用。部署者接入反向代理时，还应确保配置的 APP_ORIGIN 与用户实际访问的 HTTPS 地址一致。
