# 为什么请求体上限要按字节算

长正文和封面可以放进同一个 JSON 请求。若服务端先把整个请求读入内存，再用字符串长度判断大小，限制生效前就已经接收了整个请求。中文正文的字符数也可能远小于它在网络上的字节数。

稿栈设置了 1,150,000 字节的上限。若请求声明的长度已超限，服务端可直接拒绝。即使没有长度声明，程序也会逐块累计实际读取的字节数，达到超限条件便停止读取。最后才做 JSON 解析与字段校验。中文字可能恰好跨越两块，因此解码器以流式模式工作，在最后刷新时检验编码是否完整。

运行 `node --test tests/publication.test.mjs`，查看 `rejects cross-origin writes and oversized JSON`。样本含 400,000 个「稿」字，UTF-8 编码下仅正文就有 1,200,000 字节，因此请求返回 400。这个限制针对单个请求，部署端的失败登录限速仍需单独配置。
